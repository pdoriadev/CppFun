# Sample textures

Seven 512×512 PNGs for trying out texture mapping. All drawn from scratch by
`tools/make_textures.py` — nothing downloaded — so the whole set is
unambiguously safe to hand to a class: no licence to track, no attribution to
get wrong, no link to rot.

Regenerate or extend them with:

```bash
python3 tools/make_textures.py
```

512×512 and power-of-two on purpose: mipmapping wants it, and a texture that
tiles cleanly at 512 also tiles cleanly when the driver halves it.

## What each one is for

| File | Reach for it when |
|---|---|
| **`uv-grid.png`** | **a mapping looks wrong.** Every cell is individually labelled `A1`–`H8`, and the `u = 0` / `v = 0` edges are marked. You can see at a glance which way is up, where the seam is, and whether the parameterisation is stretched — none of which a checkerboard tells you |
| `checker.png` | distortion and stretch. Squares stop being square where the mapping is uneven — best on a floor slab scaled up, where the perspective is obvious |
| `brick.png` | tiling. Seamless in both directions, so it shows whether repeats line up. Good on cubes and scaled floors |
| `wood.png` | **axis alignment.** Directional grain, so a mapping rotated 90° is obvious. A checkerboard looks identical rotated; this does not |
| `earth.png` | spheres. Equirectangular — longitude across, latitude down — matching what `Sphere` generates, so the poles converge the way a real map does |
| `gradient.png` | filtering and banding. Smooth and featureless on purpose: nothing to alias against, so what you see is the interpolation |
| `marble.png` | **minification aliasing.** Busy and high-contrast. The ray tracer samples bilinearly with no mipmaps, so a marble surface small in frame will shimmer in a trace before it does in the viewport |

## Which shapes can use them

Texturing needs texture coordinates, and not every shape has a
parameterisation yet. The Material panel says so when you select one.

Every shape in the editor has a parameterisation now. Which one it gets depends
on what the shape knows about itself:

| Shape | Mapping | Why that one |
|---|---|---|
| `Sphere` | spherical | its own generation loop already *is* a UV map — u round the equator, v pole to pole |
| `Cube` | planar per face | eight corners, twenty-four distinct (corner, face) pairs, so no per-vertex map can exist |
| `Pyramid`, `Icosahedron` | planar per face, projected | flat faces with no natural parameterisation; the normal comes from the triangle itself |
| `Möbius`, `Custom` | parametric grid | generated by a nested (i, j) loop, so i and j are the map |
| `Teapot` | cylindrical | arrives from a table of Bézier patches as a plain triangle soup, with nothing to reuse |
| Curve surfaces (`ImportCurve`) | cylindrical | a surface of revolution *is* a cylinder in the sense that matters |
| Imported `.obj` | whatever the file says | uses the `vt` lines when present; untextured without them |

Two of these seam-repair per triangle (`Teapot`, curve surfaces): a triangle
spanning the back of the mesh has corners at u = 0.98 and u = 0.02, and
interpolating between them the long way squeezes the whole image, mirrored, into
one triangle — a bright vertical scar. The fix pushes the low corners past 1.0,
which means the same point in space holds different u values depending on which
triangle is asking. That is why those maps are per corner rather than per vertex.

An imported `.obj` with no `vt` lines still renders untextured: the `hasTexture`
uniform stays false and it draws exactly as it did before. That is deliberate
rather than an oversight — untextured rendering has to stay bit-for-bit
identical to what it was before texturing existed, which is what the exact image
sums in `raytrace_test` verify.

## Both renderers

Everything here works in the rasterized viewport **and** in a ray-traced
render. The tracer samples the decoded pixels on the CPU — it never touches
the GPU — and multiplies them into the base colour exactly as the fragment
shader does, so a trace and the viewport agree.

The one difference: the viewport gets `GL_LINEAR_MIPMAP_LINEAR`, the tracer
plain bilinear. Hence `marble.png` above.
